# yek命运织机

把正文里的人物做成世界书里的正式角色 —— SillyTavern 第三方扩展。

A SillyTavern extension that turns incidental characters from your roleplay
into fully-formed world book entries.

> 仅限成年内容创作使用。Adult content tooling only.

## 功能

- **自动检测**：每轮回复后扫描最近几楼，列出值得做成角色的人物
- **一键生成**：一次性产出 4 条世界书条目
- **出场导演**：让角色自己出场，不靠你手动触发关键词
- **更新已有角色**：重新分析后逐条对比，只更新你勾选的；也可以直接查看/编辑条目全文，改完自动同步世界书，或让模型自动重写
- **人物变化**：怀孕、关系变化、身份暴露等长期状态单独记录，写进世界书常驻条目，AI 每轮可见；每 3 楼自动检测更新
- **剧情时间自动追踪**：每轮从正文识别剧情时间（几点/第二天/过夜），自动写进常驻条目，AI 不再沿用旧日期
- **流式生成**：生成角色模板时内容边写边显示（右下角小窗），可随时终止
- **可撤销**：每次写入记录操作明细，一键回滚

## 出场导演

「新角色永远不出场」是个死锁：她的条目靠名字触发，可她不出场就没人提她的名字。

导演在每次生成前算出该让谁出场，只往提示词里注入约 100 字：

| 档位 | 触发条件 | 做什么 |
|---|---|---|
| **出场** | 最近几楼出现了她的场景词 | 提示她可以在这里登场，给出出场方式 |
| **轻提** | 很久没出场、场景对不上 | 不让她出场，只让认识她的人提一句，或留下她的痕迹 |
| **不提** | 还没到间隔门槛 / 激烈场景 | 什么都不注入 |

注入的文字带 `scan=true`，会顺手点亮她那几条绿灯条目 —— **人设由世界书带进来，导演不重复写**。

几条硬约束：

- 从没出场过的人不会被「轻提」（主角不认识她，一条短信或一件外套都会突兀）
- 「谁提一句」必须是**在场且认识她**的人 —— 不认识她的人提她等于穿帮
- 随机偶遇默认关闭，开了才会在场景不匹配时硬插
- 读数据库维护的「重要角色表」：在场的人不推荐，在别处的人降权

## LLM 扫描角色

世界书的命名千奇百怪（`角色丑`、`角色丑性格补充`、`角色寅-猫妖-（人设核心）`），靠正则猜必漏。

点一下「LLM 扫描角色」，把条目名和关键词发给模型（约 1 次请求），让它归并出人物清单。
结果按条目指纹缓存，内容不变不重扫。

四级识别（从高到低）：

1. LLM 扫描结果
2. 「人物关系速览」这类总表
3. `角色卡 X` / 手动填写的名字
4. 条目名里含「人设 / 核心 / 设定」的

## 安装

### 方式一：直接从 GitHub 安装（推荐，可自动更新）

酒馆 → 扩展 → 安装扩展 → 粘贴本仓库地址：

```
https://github.com/yeklow/yek-FateLoom
```

### 方式二：手动

把整个文件夹放进 `SillyTavern\public\scripts\extensions\third-party\yek-FateLoom\`，重启酒馆。

### 方式三：酒馆助手脚本

如果装了 [JS-Slash-Runner](https://github.com/N0VI028/JS-Slash-Runner)，把 `yek-FateLoom.script.js` 的内容粘进脚本库即可，不用重启。

> 单文件版由 `build-script.mjs` 从 `index.js` + `style.css` 自动生成，与扩展版同步。`r`n> 改完源码跑一次 `node build-script.mjs` 即可。

## 生成的条目

一个角色 = 4 条 + 1 段：

| 条目 | 内容 |
|---|---|
| `角色卡 <名>` | 基调 / 核心身份 / 定位四件事 / 背景 / 外貌 / 语言风格 / 性格 |
| `身体配置 <名>` | `<body_configuration>` YAML |
| `性癖档案 <名>` | `<sexual_profile>` YAML |
| `<名>_行为落地指南` | 行为路线：触发条件 / 动作表现 / 重点细节 |
| （追加进「行动路线」） | 「介入机会」：什么信号下她可以出场 |

关键词里**强制包含角色名本身**（第一位），否则导演注入名字时扫不到她的条目。

## 边界设计

三条内容不写重：

- **角色卡** = 人设，外貌只到发型、面部、服饰、整体轮廓
- **身体配置** = 所有身体细节，尺寸形状质感、非人形态
- **性癖档案** = 性相关的敏感带、弱点、偏好、技巧

## 人物关系

生成时要求角色有具体的社会连接：

- `与{{user}}的关系` 必须具体（不能写「陌生人」）
- `rel_list` 至少列一个在「已存在」名单里的具体人物，并说明她为什么会被这个人提起

关系不是装饰 —— 它是「她能自然地被人提起」的前提。

## 安全

- 只按条目名精确匹配（`角色卡 <名>` 这类），不碰你手写的条目
- 原地修改 content，不删除重建，uid 和顺序都保留
- uid 用 BigInt 处理（超过 2^53 时普通 `++` 会失效导致反复覆盖同一条）
- 记录内容指纹，你手改过的条目更新时会警告
- 操作日志可一键撤销，体积 KB 级（存「改了什么」而不是整本快照）

## 配置

侧栏「API 配置」独立设置，不占用酒馆主 API：

- 连接方式：自定义端点 / 跟随酒馆主 API
- 端点、API 密钥、模型名（可点「加载模型」拉列表）
- 额外请求头（opencode 这类端点需要 `x-opencode-session`）
- 安装时密钥写入 SillyTavern secrets，不落到设置文件里

# Galgame / 视觉小说模式（Galgame Mode）

## 安装
1. 把整个 yek-FateLoom 目录放到 SillyTavern/data/default-user/extensions/third-party/
2. 重启酒馆，在扩展面板里启用「yek命运织机」
3. 世界书里要有「角色卡 X / NSFW档案 X」形式的条目（Galgame 从中读取角色名和立绘）

## 核心设置（素材与显示页）
- **AI 标注说话人**（默认开）：让生成正文的模型在每句台词前输出 【角色名】：“台词”，Galgame 100% 按标注显示姓名牌/立绘；没标注的旧消息回退自动识别
- **聊天隐藏标注**（默认开）：聊天正文里不显示 【角色名】： 前缀（只影响显示，聊天记录里仍保留）
- **截断自动重roll**：卡住/截断/漏标过多时自动重新生成，可设置次数、等待时间、判定秒数
- **立绘**：按 --- 场景分隔线分场景显示，每个场景只显示本场景的角色；没有 --- 时用「走进/回到 + 地点」「次日/第二天」识别转场

## 诊断
按 Ctrl+Alt+D 打开诊断面板：当前段落/说话人/场景立绘/名字表/自动重roll 状态 + 最近事件，点「复制 JSON」可直接发我定位问题。

## 开发 / 测试
`ash
npm run build   # 重新生成 yek-FateLoom.script.js 单文件版
npm test        # 跑说话人识别 V2 的 20 条回归测试（node --test）
`

## 常见问题
- **姓名牌/立绘偶尔错**：Ctrl+Alt+D 看说话人来源（标注/自动识别）。模型漏标时扩展会提示，漏标多会自动重写一次。
- **后台表情/角色识别不生效**：后台模型若为推理模型，思考可能烧完 token；扩展会自动关闭思考重试一次，诊断面板会有 g_llm_* 记录。
- **正文被截断**：优先怀疑 Google SAFETY 安全过滤（finishReason: SAFETY），扩展无法绕过，可换模型或改写内容。
- **和其它扩展打架**：SP-数据库/记忆库静默生成时扩展会让路；仍冲突可把「等 N 秒再重roll」调大。
